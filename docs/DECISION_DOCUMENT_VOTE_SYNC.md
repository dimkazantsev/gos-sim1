# ГОС.ID — согласование решений, голосований и правовых документов по 16 этапам

Дата технического среза: 18.10.2026. Основа: действующая PostgreSQL/Supabase (структура, триггеры и процедуры), `components/game/StageArtifacts.tsx`, `components/game/proceduralVoting.ts`, `components/game/LegislativeSessionLab.tsx`. Срез не заменяет покомпонентное тестирование конкретного этапа.

## Инварианты общей системы

1. Источник истины — конкретное принятое решение (UUID/результат выборов, протокол, постановление), а не текст новости.
2. Правовой документ хранит неизменную ссылку на исходное событие. Повторные транзакции и запросы должны быть идемпотентны.
3. «Подготовлен», «принят», «подписан», «опубликован» различаются. Генератор не может имитировать подпись, принятие или публикацию, которых не было.
4. Настройки голосования соответствуют типу правового акта, органу, стадии документа, действующим правилам игры и проверенным полномочиям. Голосование по вопросу, связанному с заседанием, недоступно до фактического начала рассмотрения.
5. Завершение заседания, отзыв или перенос вопроса немедленно блокирует голосование; бюллетени и результаты не теряются.
6. Все права проверяются на сервере; UI лишь показывает доступность действия. Контрольная нагрузка: не менее 40 участников.
7. Условие завершения этапа проверяет результат и необходимые официальные документы отдельно. Предыдущая система фиксации оценочного срока и автоматического продления документов сохраняется.

## Вопросы владельцу перед дальнейшими миграциями

1. Юридический момент публикации постановлений: сразу после подтверждённого голосования или только после подписи уполномоченного лица?
2. По заместителям ГД — один акт на двоих или отдельный на каждого?
3. По пяти комитетам — акт сразу после последнего избрания или только после окончательного распределения 450 мандатов?
4. При снятии вопроса с повестки и последующем повторном рассмотрении — хранить прежнюю карточку голосования с историей или создавать новую попытку?
5. Допустимы ли автоматические записи прошедших этапов без отдельного утверждения преподавателя? В PR №264 создаются только подтверждённые **черновики**, не опубликованные акты.
6. Для органов, чьи решения принимаются без коллегиального голосования (например, указы), показывать ли в разделе голосований отдельную карточку «Не требует голосования»?

## Критерии следующих точечных PR

- Каждый обработчик: доказательство события, источник данных, идентификатор, разрешённые статусы и роли, отмена/пересмотр, публикация и проверка нагрузки.
- Не пересчитывать оценки и не открывать ранее закрытый этап ради выпуска документа.
- Прогонять только затронутые механизмы и непосредственные зависимости. Перед выпуском — необходимые регрессии, проверка прав, RLS и целостности.
