# GOS//SIMS — архитектура учебной симуляции

## Идея

GOS//SIMS — многопользовательская учебная среда для моделирования государственного и политико-административного управления. Студенты входят по ФИО и коду сессии, получают роли, совершают действия и взаимодействуют через каналы. Преподаватель управляет раундами, событиями и последствиями.

## Роли

**Студент:** профиль, роль, команда, персональные задачи, действия, документы, чат, аудио/видео, журнал собственного участия.

**Преподаватель:** создание игры, выдача кодов, назначение ролей, запуск/пауза раунда, публикация событий, принятие/отклонение действий, изменение показателей, просмотр участников и аудит.

**Наблюдатель:** read-only режим для экспертов или гостей.

## Игровой цикл

1. Преподаватель создаёт игровую сессию.
2. Студенты входят по коду.
3. Назначаются роли и команды.
4. Преподаватель открывает раунд.
5. Система показывает общие и ролевые события.
6. Игроки обсуждают ситуацию и отправляют решения.
7. Преподаватель принимает, отклоняет или возвращает решения.
8. Последствия отражаются на показателях государства.
9. Действия и сообщения сохраняются в аудит.
10. После занятия журнал можно использовать для разбора.

## Основные сущности

- games — игровые сессии;
- game_members — участники и роли;
- rounds — игровые раунды;
- state_metrics — показатели государства;
- game_events — события;
- player_actions — решения игроков;
- chat_channels / channel_members / chat_messages — коммуникация;
- game_documents — документы;
- missions — персональные и командные задания;
- audit_log — неизменяемый журнал;
- storage bucket game-media — аудио, видео и файлы.

## Realtime

Supabase Realtime подписывает клиента на изменения игр, метрик, событий, действий и сообщений. Это позволяет преподавателю инициировать событие, которое сразу появляется у всех подключённых игроков.

## Безопасность

Клиент использует только anon key. RLS ограничивает строки по членству в игре. Преподавательские изменения доступны только участнику с kind=teacher. Для приватных каналов дополнительно проверяется channel_members. Медиа хранятся в приватном bucket и выдаются через signed URL.

## Дальнейшее развитие

- редактор сценариев без программирования;
- автоматические триггеры событий по метрикам;
- карта акторов и коалиций;
- голосования парламента;
- согласование документов по маршрутам;
- скрытые вводные для отдельных ролей;
- push-уведомления;
- replay всей сессии по времени;
- детальная оценка вклада студента;
- экспорт отчёта преподавателя;
- публичный экран для проектора;
- несколько параллельных государств/групп.

## Принцип переноса исходных правил

Текст исходной игры должен быть превращён в конфигурацию: роли, полномочия, этапы, документы, ограничения, события, формулы показателей, права видимости и условия завершения. Интерфейс при этом менять не требуется.
