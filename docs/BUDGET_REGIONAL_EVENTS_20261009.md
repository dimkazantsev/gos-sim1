# Региональные события и заявки на расходы

Каталог `content/budget-regional-events-2026.json` содержит 16 авторских учебных ситуаций для этапа «Бюджет». Каждая связывает регион на карте, обоснование потребности, подробную смету, заявку на федеральную поддержку и показатель ожидаемого результата. Ситуации не являются сообщениями о реальных происшествиях; суммы и исходные показатели — параметры игры. Названия и коды регионов взяты из `data/regions.json`.

Последовательность соответствует исходным правилам игры, этапу 13: расчёт расходов и обоснования → проект бюджета и коллегиальное решение Правительства → предварительное рассмотрение → три чтения ГД → дальнейший маршрут ФЗ. Подготовленная заявка и решение по событию не означают перечисления денег. Событие даёт основание для рассмотрения расходов; заявка учитывается в проекте бюджета отдельно.

## Контракт данных

Сохраняется существующая структура `event_cases`: `case_key`, `title`, `situation`, `category`, `seriousness`, `audience`, `allowed_roles`, `decision_options`, `effect_plan`, `source_url`, `source_note`, `verified`, `status`, `comic_scene`.

Все новые события имеют `status: "ready"`, `audience: "group"`, `seriousness: "serious"`, `comic_scene.format: "budget-dossier"`. `source_url` равен `null`, `verified` равен `false`: каталог не приписывает авторским ситуациям проверку реальных новостей или официальных показателей. Основания вариантов явно отсылают к учебной процедуре, а не пересказывают действующее законодательство.

`comic_scene.region_code` и `region_name` связывают событие с картой. `comic_scene.case_key` совпадает с основным ключом. Вложенный объект `comic_scene.budget_request` имеет следующие поля:

| Поле | Значение |
| --- | --- |
| `section_key` | Ключ отраслевого раздела расходов из `data/federal-budget-2026.json` |
| `kind` | `subsidy` для целевого проекта; `grant` для дотации общего характера |
| `amount` | Предлагаемая федеральная сумма, **млн рублей** |
| `cofinancing` | Собственные средства региона, **млн рублей** |
| `currency_unit` | `million_rubles` |
| `estimate` | Массив строк `{name, amount}` с затратами **в млн рублей** |
| `justification` | Обоснование запроса и документы, которые должны его подтверждать в игре |
| `expected_result` | Результат после финансирования и исполнения, а не сразу после события |
| `indicator` | `{name, baseline, target, unit}` для проверки результата |

Для каждой заявки выполняется `sum(estimate.amount) = amount + cofinancing`. Федеральные расходы содержат только `amount`; региональное софинансирование показывается отдельно. Целевые субсидии относятся к отраслевым разделам. Единственная дотация общего характера относится к разделу `14`; её детализация поясняет размер заявки и не создаёт дополнительные отраслевые заявки.

## Последствия выбора

У каждого события три различных варианта. Каждый явно задаёт `authorized_roles`, `lawful`, `legal_basis`, `protects_role_interest`, `public_interest`, `trust`, `description`, `news` и `fiscal_effect`. Используются должности из существующей модели игры: Министр финансов, Председатель Правительства, Губернатор, Глава региона и соответствующий профильный министр. Правомерность размечена именно для учебной процедуры.

`fiscal_effect` совместим с существующим `private.fiscal_event_outcome()`:

| Поле | Значение и применение |
| --- | --- |
| `enterprises` | Целое изменение числа действующих предприятий относительно сохранённой начальной базы |
| `activity` | Добавочное изменение регионального множителя активности; через него меняются модельные базы прибыли и потребления |
| `cost` | Добавочное изменение регионального множителя текущих издержек |

Каталог не использует `transfer_in`, `budget_effect` или дополнительные федеральные расходы внутри исхода события. Стоимость строительства целиком остаётся в заявке и не прибавляется второй раз к расходам из `fiscal_effect`.

В трёх ситуациях роста новые действующие предприятия ещё не входят в сохранённую начальную базу. Выбор учитывает фактически продолжающие работу предприятия. Обещанные будущие подключения, выпускники, урожай, введённые объекты и экономия от строительства не повышают текущие доходы. Эти результаты проверяются после финансирования и исполнения проекта.

Идемпотентность уже обеспечивает помощник: перед применением исхода он проверяет запись в `fiscal_change_ledger` по игре, событию и региону. Повторный просмотр досье или заявки не должен повторно применять изменение базы. Ничья не применяет вариант. Создание заявки связывается с исходным событием отдельно; изменение региональной базы не подтверждает выделение трансферта.

## Проверка каталога

Проверка JSON выполнена 09.10.2026: 16 уникальных ключей, названий, ситуаций и регионов; 48 вариантов; 63 строки смет; восемь действующих разделов расходов. Пересечения ключей с `content/budget-cases-2026.json` отсутствуют. У всех заявок сходятся смета и федеральная/региональная суммы, есть обоснование и отличный от исходного целевой показатель. Во всех вариантах заполнена разметка полномочий; финансовые эффекты содержат только поддерживаемые ключи и конечные числовые значения. В названиях, описаниях и вариантах первая буква заглавная.

Отдельная содержательная проверка исключила немедленное зачисление трансфертов и доходов от ещё не построенных объектов. Для применения в игре нужны миграция наполнения каталога и проверка связи «событие → заявка → проект бюджета → ФЗ» на уровне базы; эти изменения выполняются в общей переработке бюджета.
