| Область | Ошибка и результат исправления |
| --- | --- |
| Права RPC | Отсутствующий участник мог получать NULL вместо пустой роли. Проверки назначений и государственных программ теперь явно отклоняют чужой доступ; переходы программы проверяют текущее состояние. |
| Документы | Извлечение текста было доступно без входа, multipart разбирался до ограничения общего объёма. Теперь вход и действующее участие проверяются до чтения тела; облачный импорт дополнительно проверяет владельца ссылки и её игру. |
| Разбор файлов | DOCX/PDF обрабатывались в основном процессе. Добавлены отдельный worker, пределы ZIP/XML, 200 страниц PDF, 10 секунд разбора и ограничения V8 heap. Обычные PDF/DOCX/TXT сохраняют поддержку; сложный файл предлагает ручной ввод. |
| Облачные экспорты | Ограничены весь запрос, размер ответа, время и разрешённые HTTPS-хосты каждого перенаправления. Неподдерживаемый двоичный экспорт возвращает ошибку формата. |
| Storage и чат | Файл привязан к игре, каналу и автору. Закрыта подмена пути и назначения при обновлении профиля/партии; загрузка game-media ограничена 25 МиБ. Повтор отправки не переносит прежний файл в другой чат или аккаунт. |
| Назначения и готовность | Исключены архивные студенты из проверок активного состава. Один кандидат не может одновременно занимать два министерских места. Готовность этапа 6 одинакова в одиночном и общем RPC; рефлексия учитывает действующих студентов. |
| Калькуляторы | Исправлен Droop при входных процентах и региональные квоты. Сервер проверяет партии, целые неотрицательные итоги, 450/89 мест и согласие результата с формулой/входным снимком. Исправлена неоднозначная SQL-переменная региональных мандатов. |
| Оценивание | Штраф 0,5 больше не округляется до целого. Журнал хранит оценку после штрафа. Для окончательной целой оценки преподаватель делает явный выбор. |
| Обновления клиента | Поздний ответ другого класса/пользователя или старого запроса не восстанавливает прежние данные и права. Ошибки чтения видны; черновики, ручной выбор кандидата и результаты более нового запроса сохраняются. |
| Редактор документов | Позднее извлечение и загрузка досье не заменяют новый файл, документ или введённые реквизиты. Смена пользователя, шаблона и источника отменяет прежнее извлечение. |
| Ручные события | Форма не передавала правовую разметку, а RPC её отбрасывал. Это превращало ручные решения в нарушения полномочий. Теперь преподаватель явно задаёт правомерность, полномочные должности и основание; сервер проверяет и сохраняет поля, включая `lawful:false`. |
| Сборка | Node требуется >=22, как у установленного unpdf. Серверные manifest-файлы включают worker и все 220 файлов его зависимостей. Добавлены no-store для API и защитные HTTP-заголовки. CSP ограничивает frame-ancestors, base-uri и object-src; полной политики script-src пока нет. |

## Что осталось

1. **Три moderate предупреждения зависимостей.** Цепочка Mammoth → argparse → sprintf-js содержит [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). У advisory нет исправленной версии; предлагаемый npm downgrade Mammoth не применялся. В приложении используется библиотечное извлечение текста, а проблемная цепочка относится к CLI; worker дополнительно ограничен. Это снижает достижимость, но предупреждение не объявлено устранённым.
2. **Защита от скомпрометированных паролей отключена.** Это остаётся настройкой Supabase; её изменение не выполнено. [Описание настройки](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
3. **Производительность требует измерения при реальной нагрузке.** Финальный advisor сообщает о 199 FK без покрывающего индекса, 70 неиспользованных индексах и 29 группах пересекающихся permissive-политик. Это кандидаты на оптимизацию, а не доказательство сбоя. Индексы не удалялись без измерений; общие таблицы сторонних приложений не перерабатывались. [FK](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [индексы](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index), [политики](https://supabase.com/docs/guides/database/database-linter?lint=0006_multiple_permissive_policies).
4. **Предупреждения о доступных RPC и анонимных сеансах остаются.** Два намеренно публичных RPC обслуживают публичный опрос; 300 SECURITY DEFINER RPC доступны authenticated. Такие предупреждения сами по себе не доказывают обход прав. Анонимные студенческие сеансы предусмотрены приложением и всё равно должны проходить проверки участия. Три таблицы с RLS без политик закрыты по умолчанию. [Публичные RPC](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated RPC](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [таблицы без политик](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
5. **Один объединённый SQL-набор не засчитан как PASS.** `database-flow-check.sql` обновлён под созданные тестовые личности, текущий каталог из 200 событий, бонус полномочий и большинство всех назначенных участников. После исправлений полный запуск и сокращённый вариант не получили итог через коннектор: `Invalid or expired requestState`. Выявленная ошибка разметки исправлена и отдельно подтверждена реальными 20 SQL-проверками; это не заменяет успешное выполнение всех оставшихся утверждений старого набора.
6. **Границы проверки.** Не проводились учебная игра с живой аудиторией, нагрузочное испытание на сотнях одновременных пользователей, восстановление из резервной копии и атаки тяжёлыми файлами. Публичный учебный опрос не подтверждает «один голос на реального человека». Наличие успешных тестов не означает доказанного отсутствия всех ошибок.
