# Deployment

## 1. Supabase

GOS//SIMS использует Supabase Auth, PostgreSQL, Realtime и Storage.

1. Создайте отдельный Supabase project.
2. Примените `supabase/schema.sql`.
3. В **Authentication → Providers / Sign In** включите **Anonymous Sign-Ins**.
4. Рекомендуется включить CAPTCHA/Turnstile перед массовым использованием со студентами.
5. Возьмите:
   - Project URL
   - Publishable key (`sb_publishable_...`)

Анонимный вход здесь используется как техническая сессия: студент вводит ФИО и код игры, а Supabase выдаёт ему уникальный `auth.uid()`. Доступ к данным затем ограничивается RLS.

## 2. Vercel

Проект готов к импорту из корня репозитория:

- Framework: Next.js
- Build command: `npm run build`
- Root directory: repository root

Нужные переменные:

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
```

Обе переменные являются клиентскими. **Никогда не добавляйте service_role / secret key в NEXT_PUBLIC_*.**

## 3. Проверка после публикации

1. Открыть главную страницу.
2. Переключиться на «Преподаватель → Создать игру».
3. Ввести название, код игры, код преподавателя и отдельный код студентов.
4. Убедиться, что создаётся игровая сессия.
5. Открыть сайт в другом браузере/инкогнито как студент.
6. Войти по коду игры + студенческому коду.
7. Проверить:
   - появление участника у преподавателя;
   - отправку решения;
   - Realtime-обновление;
   - общий чат;
   - запись аудио/видео;
   - принятие/отклонение решения преподавателем.

## 4. Важное ограничение anonymous auth

Анонимный пользователь не сможет восстановить ту же Supabase-сессию после выхода или очистки данных браузера. Для учебной аудитории это нормально как MVP, но перед долгосрочным использованием стоит добавить восстановление сессии по одноразовому коду или обычную авторизацию.
