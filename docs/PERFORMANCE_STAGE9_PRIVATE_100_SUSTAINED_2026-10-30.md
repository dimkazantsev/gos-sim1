## Новая проверка

Дополнительный режим того же реального локального Private Realtime/Auth-теста запускается отдельным GitHub Actions workflow **только по PR, который меняет этот QA-workflow либо его тестовый сценарий**. Обычные коммиты и правки игровых компонентов не запускают 20-минутную нагрузку.

Создаётся одноразовый пустой локальный Supabase. URL строго `localhost`/loopback; используются локальные Auth/JWT, PostgreSQL, PostgREST, WebSocket. Проект `bderfrcfuhnutuoyudje` и другие приложения не затрагиваются.

Проверка выполняет:

1. 100 самостоятельно авторизованных студентов, преподаватель, гость, чужая игра, анонимный доступ; приватная RLS-проверка и запрет клиентского Broadcast.
2. 100 студенческих приватных WebSocket, плюс два разрешённых; Presence, создание серверных уведомлений.
3. 20 минут: не более **одного адресного RLS-чтения на активного студента в минуту**. На 8-й и 9-й минутах отключаются 50 студентов, после этого проверяются повторная подписка и Presence.
4. **10 серверных уведомлений** из изолированного документа с двухминутным интервалом. Каждое должно быть получено всеми разрешёнными активными WebSocket, включая преподавателя и гостя; 100% квитанций или тест FAIL.
5. Ожидается **1 900 успешных адресных чтений**, **920 получений Broadcast**, 50 восстановлений подключений и 0 ошибок. Измеряются только реальные задержки этих чтений p50/p95/p99, суммарный размер их JSON-ответов, не общий egress.
6. После теста весь локальный Supabase уничтожается без backup; нет публичной публикации тестовых данных.

## Точное определение статуса

План и код в PR — **не результат нагрузочного теста**. Успех засчитывается только после завершения GitHub Actions со статусом SUCCESS и проверки отчёта. Даже при успехе это только **частичная комплексная приёмка**: не проверяются все 16 этапов, документы в Storage, реальное время 100 браузеров, редактура и одновременное начисление во всех подсистемах.
