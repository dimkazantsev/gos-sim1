# PR №52 — production readiness audit

Дата: 12.10.2026

## Подтверждено в рабочей Supabase

- Банк: 1000 вопросов; 1000 `verified=true`; 1000 `legal_review_status=approved`; 0 pending; 0 rejected.
- Наименования НПА нормализованы до 23 канонических позиций.
- Вопрос №842: реквизиты уточнены до статьи 83, пункта «д.1», и статьи 112, части 2 Конституции РФ.
- Серверные `blitz_open` / `blitz_answer` защищены от конкурентного двойного открытия и ответа до открытия карточки.
- `anon` не имеет EXECUTE на пользовательские RPC «Блица»; прямой SELECT банка вопросов для `anon/authenticated` закрыт; прямые INSERT/UPDATE заданий студентам не предоставлены.
- Интеграция ВСН установлена и включена для игры «ПАУ» с этапа 1: 0,30 кейсы + 0,30 правомерные действия + 0,30 правильность «Блица» + 0,10 полнота.
- На момент включения: игра на паузе, этап 1, студентов 0, оценок 0, назначений 0. Ретроактивного пересчёта существующих оценок нет.
- Активных cron-задач «Блица» нет. Это не блокирует выдачу: клиент вызывает `blitz_issue_today`, а пропущенные дни восстанавливаются при следующем входе.
- `blitz_assignments` намеренно не входит в production Supabase Realtime publication. Production-транспорт «Блица»: Auth + RPC + RLS/REST.

## Проверки ветки

Release CI включает:
1. production build/regression;
2. teacher UI/stage regression;
3. budget simulator regression;
4. изолированную PostgreSQL concurrency-проверку 30 участников;
5. локальный Supabase-контур с 30 реальными Auth-сессиями, RPC, RLS/REST, запретом чужого ответа и сериализацией одновременных открытий.

Эксперимент с локальным Postgres Changes Realtime не используется как release gate: сервисный канал локального Realtime не доставлял события даже при наличии publication/replication slot, тогда как production «Блиц» этот транспорт не использует.

## Юридический статус

Проведена постатейная сверка учебного банка по указанным нормативным источникам и отдельная проверка высокорисковых переходных норм № 33-ФЗ. Статус `approved` означает допуск в учебный банк по этой проверке. Он не является независимым заключением внешнего профессионального юриста.

## Ограничение выпуска

Этот аудит не разрешает автоматически объединять PR с `main`. Merge/публикация выполняются только после отдельного разрешения владельца проекта.
